# CafeConsole Review - 2025-11-12 (Pass 2)

- **Receipt lifecycle is broken**: BeverageService creates _receipt once in the constructor and never refreshes OrderId/timestamp per order (Cafe.Application/Services/BeverageService.cs:15-26,75-80). Every new order reuses the previous ID and DateTime, violating the requirement for unique receipts and timestamps.
- **Decorator lines are misrepresented**: Customize appends the fully re-wrapped beverage to Receipt.Items for every add-on (Cafe.Application/Services/BeverageService.cs:54-64). Display() then prints the cumulative price of the whole chain for each line (Cafe.Domain/Extentions/DisplayReceipt.cs:21-34), so the receipt double-counts and never shows individual surcharges or discounts.
- **Syrup flavor flow missing**: The UI only captures a generic "syrup" token (Cafe.ConsoleUI/Menus/MainMenu.cs:111-138), the service hard-codes "vanills" (Cafe.Application/Services/BeverageService.cs:56-60), and the decorator ignores its _flavor field (Cafe.Domain/Beverages/Decorators/SyrupDecorator.cs:11-14). Users cannot add flavored syrup as specified in the brief.
- **Pricing strategies still bypass DI**: SetPricingStrategy pulls instances from PricingStrategyManager (Cafe.Application/Services/BeverageService.cs:82-85), which constructs singletons inside the domain (Cafe.Domain/Pricing/PricingStrategyManager.cs:9-25). This contradicts the brief’s request to wire strategies in Program.cs and makes testing/extending policies harder.
- **Receipts violate non-functional requirements**: The domain layer formats console-facing strings and hard-codes the $ symbol (Cafe.Domain/Extentions/DisplayReceipt.cs:15-34), while Receipt.At uses DateTime instead of DateTimeOffset (Cafe.Domain/Order/Receipt.cs:12-17). This breaks the “no I/O in domain” and “currency/locale ready” requirements.
- **Happy Hour math off**: HappyHourPricing.Apply returns subtotal * 0.8m without rounding (Cafe.Domain/Pricing/HappyHourPricing.cs:11-14), so totals like 10.005 won’t match the two-decimal acceptance criteria.
- **Observer pipeline incomplete**: Although IOrderEventPublisher exists, the contract uses Published(...) and there are no unit tests covering dispatch. More critically, the publisher/subscriber registrations live in the console project, but Cafe.Tests (required for strategies/decorators/factory/observer coverage) is still missing entirely.

Key areas to tackle next: reset receipts per order, record add-ons as separate lines, capture syrup flavors, inject pricing strategies via DI, move presentation/formatting out of the domain, fix Happy Hour rounding, and add the mandated test suite.
