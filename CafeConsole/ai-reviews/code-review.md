# CafeConsole Review - 2025-11-12

- **Missing order events & observers**: The brief requires publishing an OrderPlaced event observed by a console logger and analytics component, but there is no event contract/publisher under Cafe.Domain/Events, and the supposed observers are empty marker classes (Cafe.Infrastructure/Observers/ConsoleOrderObserver.cs:9-11, Cafe.Infrastructure/Observers/InMemoryOrderAnalytics.cs:9-11). Nothing in the application layer raises an event, so the observer pattern is absent.
- **Receipt output is inconsistent with decorator usage**: BeverageService.Customize wraps the beverage with each decorator and appends that entire decorated object to the receipt item list (Cafe.Application/Services/BeverageService.cs:52-61). When eceipt.Display() renders the list it prints each cumulative beverage cost (Cafe.Domain/Extentions/DisplayReceipt.cs:21-34), so the receipt shows duplicate, inflated amounts and never lists an explicit discount line as required.
- **Syrup flavor flow is unimplemented**: The UI only captures generic add-on tokens and never prompts for a syrup flavor (Cafe.ConsoleUI/Menus/MainMenu.cs:109-145), the service hard-codes "vanills" whenever it sees "syrup" (Cafe.Application/Services/BeverageService.cs:54-58), and the decorator never stores or exposes the flavor (Cafe.Domain/Beverages/Decorators/SyrupDecorator.cs:9-14). Users cannot add flavored syrup even though it is a core requirement.
- **Pricing strategies bypass DI**: Instead of injecting an IPricingStrategy, SetPricingStrategy fetches a static instance from PricingStrategyManager (Cafe.Application/Services/BeverageService.cs:77-81, Cafe.Domain/Pricing/PricingStrategyManager.cs:9-25). This violates the brief’s emphasis on wiring strategies in the composition root and makes it harder to add or test new pricing policies.
- **Domain layer hard-codes presentation & currency**: The Receipt.Display extension formats output inside the domain project and embeds the $ symbol (Cafe.Domain/Extentions/DisplayReceipt.cs:15-34), contradicting the requirement that the domain stay I/O free and currency-agnostic.
- **Testing gap**: The solution lacks the Cafe.Tests project described in the brief, so none of the required unit tests for factories, decorators, pricing strategies, or observer dispatch exist.
